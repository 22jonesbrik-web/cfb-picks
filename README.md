# CFB Picks

A private, mobile-first college football pick'em for a small friend group. This is a new standalone project in `cfb-picks`; it is not part of the `$50 Experiment`.

## Local setup

1. Install Node.js 20+.
2. Run `npm install`.
3. Create a Supabase project and copy its Project URL and anon key from **Project Settings > API**.
4. Copy `.env.example` to `.env.local` and set the two public Supabase values plus the service-role key. Never expose the service-role key to client code.
5. Open **SQL Editor** in Supabase and run migrations `001_initial.sql` through `009_fix_game_upsert.sql` in order.
6. Set `OWNER_EMAIL` to the email that should receive owner access and `OWNER_USERNAME` to the matching imported league username. For your account, use `OWNER_USERNAME=Bridger-Jones`. Register that email through `/register`; its password is stored only as a salted scrypt hash.
7. Confirm the `contests`, `contest_members`, `users`, `weeks`, `games`, `contest_games`, `picks`, `admins`, and `admin_audit_log` tables exist.
8. Run `npm run dev` and open `http://localhost:3000`.

Before production verification, set the Supabase variables in `.env.local`, set both demo flags to `false`, and run `npm run check:production-env`. The command checks configuration without printing secret values. Then apply migrations `001` through `007` in the Supabase SQL editor and run the app against that project.

To create a secure player PIN hash for `supabase/seed.sql`, run `npm run hash-pin -- 1234` and paste the output into the seed file. The command prints only a salted scrypt hash, never the PIN in database format.

For a local UI preview without Supabase, set `DEMO_MODE=true`, `NEXT_PUBLIC_DEMO_MODE=true`, and any local `SESSION_SECRET`; use `Bridger` / `1234`. Do not enable demo mode in production. `lib/supabase/admin.ts` is the server-only service-role boundary.

## Locking rules

`weeks.pick_lock_at` is stored as UTC. The commissioner should enter the Saturday deadline using `America/Denver` conversion; never hardcode an MST/MDT offset. A contest game's effective write deadline is the earlier of kickoff and the stored weekly deadline. Other players' picks remain server-side private until the weekly deadline, even when an early game has already started.

`lib/picks/locking.ts` and `lib/server/pick-policy.ts` are the enforcement boundary. The client countdown is informational only.

## League rules

- The commissioner slate defaults to a Tuesday deadline four days before the Saturday player deadline. Contest games cannot be added or edited after that deadline without an explicit admin override.
- A week can contain at most 16 active contest games.
- Each player can submit exactly 10 picks, with confidence values 1 through 10 used once each. The server rejects duplicates, missing weights, and attempts to exceed 10 picks.
- Correct picks earn their confidence value as points. The commissioner designates one weekly tiebreaker game; each player submits that game's predicted combined final score, and the closest prediction wins the tie.
- Weekly prize money is fixed at $115 for first place, $70 for second place, and $35 for third place. Historical earnings are imported and future awards are recalculated idempotently when grading runs.
- Set `OWNER_EMAIL` in Vercel to the owner account email. Only an owner can change a user between `player`, `admin`, and `owner`; admins can manage the slate but cannot change permissions.
- Login includes a secure `Remember me` option. Remembered sessions last 30 days; unchecked sessions last up to 8 hours and have no persistent cookie.
- Signed-in users can open `/manage` to view account details and change their password. Owners and admins also get a link to commissioner tools there.

## Deployment

Import this folder as its own GitHub repository into Vercel, add the environment variables from `.env.example`, set `DEMO_MODE=false` and `NEXT_PUBLIC_DEMO_MODE=false`, and configure `picks.royalblue-ventures.com` as a Vercel custom domain. At the registrar, create the Vercel-provided CNAME for `picks` only; the root domain can remain where it is. The included `vercel.json` targets Denver (`den1`) for lower latency.

Production checklist:

1. Apply the Supabase migration and seed only real players with hashes generated by `npm run hash-pin -- 1234`.
2. Add `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, and a long random `SESSION_SECRET` in Vercel project settings.
3. Keep `SPORTS_API_KEY` empty for manual mode or add it for commissioner sync.
4. Deploy and verify `/api/health` returns `{ "ok": true }`.
5. Add the Vercel custom domain and create the registrar CNAME for `picks`.

If `SPORTS_API_KEY` is absent, use the manual commissioner workflow. Games, fixed contest spreads, and final scores should be stored in Supabase rather than fetched on normal page loads. The Vercel cron runs hourly and only performs the automatic FBS import at Sunday 10:00 AM `America/Denver`, handling daylight saving time safely. Set `CRON_SECRET` in Vercel. The sync fills the latest draft week with upcoming games and sportsbook spread suggestions; the commissioner still finalizes which games and fixed lines enter the pick'em.

GitHub Actions runs `/api/cron/update-scores` every 10 minutes and `/api/cron/daily-maintenance` on Sunday. Contestants never call the sports provider directly. Add these GitHub repository secrets: `APP_URL=https://picks.royalblue-ventures.com` and `CRON_SECRET` matching the Vercel environment variable. The commissioner can still use the Admin sync button anytime for immediate updates.
